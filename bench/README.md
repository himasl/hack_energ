# Проверочный набор

Восемь процессов энергетики, написанных так, как их обычно пишут бизнес-заказчики:
шаги не по порядку, пассивный залог («показания передаются»), неявные участники,
возвраты на доработку, документы, которые «улетают». Набор нужен, чтобы проверять
генерацию на незнакомых текстах, а не на примерах, под которые писался промпт.

В каждой папке:

| Файл | Что это |
| --- | --- |
| `input.txt` | описание процесса |
| `code.py` | эталонная схема на API `DIAGRAM`, написанная вручную |

| Процесс | Что проверяет |
| --- | --- |
| `01_tech_connection` | возврат на дозагрузку документов, параллельные мероприятия двух сторон, документы |
| `02_permit_to_work` | шаги описаны не по порядку, три параллельные операции, повторное оформление |
| `03_outage_approval` | три организации (пулы и сообщения), включающий шлюз «кого уведомить» |
| `04_emergency` | система как участник, подпроцесс, цикл «повторно локализовать» |
| `05_meter_readings` | пассивный залог, условие по сроку, ИТ-системы как хранилища |
| `06_invest_approval` | пять участников, два возврата на доработку, протокол, который никуда не уходит |
| `07_ascue_incident` | два способа старта, эскалация, параллельно с выбором по причине |
| `08_repair_materials` | частичная выдача со склада (включающий шлюз), внешний поставщик |

Прогон генерации по набору:

```bash
python -m bpmn_gen bench/ -o out/bench/          # по текстам, нужна LLM
python -m bpmn_gen bench/ -o out/bench/ --code   # по эталонам: раскладка и проверки без LLM
```

Эталоны также проверяются тестами: XSD, наложения, стрелки сквозь фигуры.
